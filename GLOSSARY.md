# Glossary

Terms as used across pi-herdr docs, the wayfinder map, and tickets. Decisions live in `wayfinder/`, not here. Updated for v0.6 (the subagent experience layer) and the spec 43 communication-protocol rework (once-delivered completion events, explicit followup, safe wake).

- **Substrate** — the session-file foundation: children are pi launched with parent-owned session files plus an injected child extension (`agent_done`, session naming, activity recorder, completion sidecars, identity strip). Everything (delivery, statuses, fork, resume, workflows) stands on it.
- **Sidecar** — a small file the injected child extension writes beside the session file: the **completion sidecar** (`<session>.exit`, typed `done`/`error`, plus the immutable per-event archive `.completion-<eventId>.json`) and the **activity sidecar** (current tool/streaming, read by the poll loop).
- **Agent** — a persistent logical addressable identity (`agentId`); a **run** is one dispatched execution (`runId` + `sequence`); a **pane** is a recyclable resource. The three are never conflated: panes close, agents and their events remain addressable.
- **Completion event** — the durable, immutable record of one run's terminal outcome (full final assistant message + typed declaration + agent/run/sequence/event identity), saved by the child before any normal pane recycle. Delivery to a receiver is arbitrated **once per receiver host** through the delivery ledger; explicit reread is the only repeat-body path.
- **Delivery ledger** — the per-receiver-host durable arbitration record (`delivered`/`pending`/`acked`), shared by push and pull so a completion body normally reaches the model exactly once; queued ≠ delivered ≠ read.
- **Send** — `herdr_send_agent`: QueueOnly ordinary correspondence. Durable accept only; never starts a turn, never interrupts, never resumes a closed pane; read at the recipient's next legitimate turn. Accepted ≠ read.
- **Followup** — `herdr_trigger_turn`: explicit dispatch of a new run. Idle starts, busy safely queues, a gone pane's retained session is resumed automatically; each acceptance gets a fresh run identity so old completion events never overwrite new results.
- **Wait** — `herdr_wait_agent_event`: wait for an event reference to become available; returns status/identity only — no body, no consumption, no ACK. Cancellation/timeout never stops the child.
- **Result** — `herdr_get_agent_result`: the consumption entry for a durable completion event. Mid-flight calls report status only (no drafts, no consumption); claimed events return a status reference; `reread:true` is the explicit repeat-body exception.
- **Push** — the delivery loop's terminal-event delivery into the orchestrator session: full final assistant message, wake governed by the `notifications` setting under the finished-parent boundary; body commitment arbitrates through the same delivery ledger as pull.
- **Notifications** — `normal` = safe run boundaries (a finished parent stays unread unless explicitly subscribed; no surprise wake), `quiet` = next natural run, no wake, `none` = stored pull-only. Explicit wake subscriptions never override quiet/none.
- **Wake subscription** — an explicit, scoped (agent/run/event), TTL-bounded, one-shot authorization (`herdr_wake_subscription`) that lets a late event start a new turn in an otherwise finished parent. Never inferred from spawn, send, or unread.
- **Direct input** — typing into a child pane (human or parent) is an ordinary channel: busy input queues safely, no marker, no takeover, no lifecycle side effects on either side.
- **Stance** — whether a run is **autonomous** (recycles its pane promptly once its result and undelivered events are durably saved, without waiting for parent ACK) or **interactive** (pane intentionally open, pings suppressed). Derives from `auto-exit`; overridable per-agent and per-spawn via `interactive`.
- **Legacy compatibility entries** — `herdr_message_agent` (the open wake/injection channel) and `herdr_resume_agent` (manual recovery) are retained but labeled compatibility/maintenance surfaces; ordinary traffic migrates to send, dispatch to followup. They never restore takeover and never bypass completion arbitration.
- **Projected state** — a status *derived* from sources (herdr inspection, activity snapshots, watchdog), never stored as ground truth. Ten: `queued`, `starting`, `active`, `waiting`, `blocked`, `interrupted`, `stalled`, `running`, `finalizing`, `gone`.
- **Watchdog** — the supervisor that flags `stalled` (inspection unhealthy / pane gone without a sidecar) and steers recovery pings; aged-but-valid `active`/`waiting` never stalls.
- **Session mode** — how a child session begins: `standalone` (fresh), `lineage-only` (header link, no turns), `fork` (parent conversation copied, truncated before the parent's last user message).
- **Launch plan** — the composed pi argv for a spawn (`--session`, `-e`, `--model`/`--thinking` from routing, system-prompt mode, identity/mode-hint blocks, task-as-artifact), handed to herdr's `agent start --kind`.
- **Routing chain** — model/thinking resolution order: spawn param > frontmatter > `models.agents.<name>` > `models.default` > parent session's model; enforce-or-error names the level that supplied a bad value.
- **Roster** — the model-facing menu of the effective agent-definition registry: winning definitions after session > project > global > built-in dedup, rendered (name, source layer, description) into a dedicated system-prompt section per request. Distinct from the **Registry** (the runtime handle map); the roster is discovery data, the registry is bookkeeping.
- **Registry** — the orchestrator-side map handle → {agent/run/sequence identity, session path, activity path, launch plan, stance, last-seen state}. Survives pane death (`gone`); the backbone of send/followup/wait/result/statuses. Pre-identity legacy records load with `identityReviewRequired` and are never fabrications — they stay pending for review.
- **Agent kind** — which CLI runs in an agent pane. v0.6 promises are pi-only; other kinds get bare pane mechanics via the passthrough.
- **Agent-message** — the protocol envelope (`<agent-message from="…" to="…">`) carrying inter-agent text; a convention, never verified. The legacy open channel (`herdr_message_agent`) is anyone↔anyone; `orchestrator` is the reserved role handle and resolves only to the sender's direct parent via `PI_HERDR_ORCHESTRATOR_PANE` (a same-name agent does not take it).
- **Orchestrator** — the role of the session that spawned you. Addressed by the reserved role handle, not by name.
- **Workflow** — a small sandboxed JS program (`agent()`/`pipeline()`/`parallel()`/…) run by `herdr_run_workflow` in the background; determinism-jailed (replayable), journaled (resumable by prefix), saved as `.pi/workflows/*.js`.
- **Determinism jail** — `Date.now()`/`new Date()`/`Math.random()` throw inside workflow scripts; a script that varies run-to-run cannot be replayed from its journal.
- **Resume journal** — per-run `<id>.workflow.jsonl` recording each settled `agent()` call; `resumeFromRunId` replays the unchanged prefix and pays only for what changed.
- **Kill-switch** — the settings gate that refuses new agent spawns. It never terminates anything; see *kill all agents*.
- **Kill all agents** — the `/subagents config` menu action that terminates every running agent pane, after confirmation.
- **Queued agent** — an accepted spawn with no pane yet because the fleet is at its concurrency cap; it starts when a slot frees.
- **Spawn depth** — how many spawns deep an agent is from the originating session; the guard against runaway recursive fleets (`PI_HERDR_SPAWN_DEPTH`).
- **Floor** — the minimum supported herdr version: ≥0.9.0, hard-checked at init (`HERDR_TOO_OLD` below it).
- **Layout mode** — the `layout_mode` setting (`grid` | `spiral`), read when a spawn's pane is created. Missing means `grid`. A change applies only to later spawns; panes already open stay where they are.
- **Grid** — the default layout. A tab holds at most three equal-width columns and two rows. The main window, on the orchestrator's tab, is the top-left cell and is no wider than an agent column. Agents fill column 2 top to bottom, then the cell under the main window, then column 3 top to bottom. A closed pane's cell is reused before the grid grows, and only inside that tab. The 7th live occupant opens another tab. A `group` gathers its agents on tabs labeled with that name (no group stays on the orchestrator's tab); when several tabs of that group have room, the new agent fills the earliest one.
- **Golden-spiral** — the `spiral` layout, kept as the rollback path. Spawn #1 splits the spawner's pane to the right; each later spawn splits the previous child's pane, alternating right then down. The existing pane keeps the larger share (ratio 0.6). `group` is not consulted.
